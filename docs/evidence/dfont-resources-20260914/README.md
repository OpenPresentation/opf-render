# Selected DFont resources in measurement and preview

The preceding fresh installed renderer embeds an entire DFont as `font/ttf`
under the default backend. The prepared backend rejects it with
`shaping-font-format`. The retained probe verifies the preceding installed
`fonts.js` hash before reproducing both failures. It does not rely on an old
working tree or a newly rebuilt package.

The registry now reads the supplied raw resource bytes within the configured
font byte limit, requires an unambiguous PostScript name, and extracts that
selected sfnt face before measurement or browser registration. Both backends
embed the selected standalone face. The complete original resource container
remains in SVG source metadata with its license; other resources, resource names,
map layout and trailing data are not lost. The preparation record exposes the
resource ID/index and `dfont-resource` reason. Reconstruction preserves selected
tables and reports invalidated DSIG removal under the existing SFNT policy.

The resource reader validates declared data/map regions, type and reference
lists, Pascal-string boundaries, resource payload lengths and unique types/IDs.
Selection rejects absent, unknown and duplicated PostScript names. Fontkit only
receives bounded sfnt resource views; extraction checks selected table ranges.
This reads bytes explicitly supplied by the caller. It performs no OS resource
lookup, font installation, network fetch or native Office operation.

## Verification

An independent fixture writer wraps the 33 unchanged bundled faces in 33
containers, each with a different first face and a selected second face, plus
a named non-font resource. Fixtures alternate data/map ordering and use data
offsets 256 and 512. Fontkit and independent FontTools 4.60.2 ResourceReader
accept their order. FontTools checks every byte of all 66 sfnt resources,
PostScript identities, resource IDs and attributes. No font is subset,
renamed or otherwise modified to generate the resource containers.

The public registry checks 66 selected-face/backend cases, single/first-face
controls and 19 malformed/selection inputs. Measurements/outlines match the
original selected font; HarfBuzz glyphs and original source ranges also match.
Missing combining-mark coverage stays an explicit error. The initial fixture
mistake assuming universal U+0302 coverage is retained separately from the
product failures; the matrix now requires identical reference/candidate errors.

Offline Chromium passes the complete 198 shaping/coverage cases and 439
nonempty, byte-identical canvas pairs. The 66 DFont pairs include every face
through both backends; prepared cases compare glyph runs, while default cases
compare Fontkit measurements/outlines. Every pair keeps natural advances within
the unchanged 0.1px gate. Actual SVG metadata retains the complete original
container and exact license. CSP, local-only requests and owned FontFace
cleanup remain checked on the same persistent page and prepared service.

The full renderer suite passes all 805 reviewed-baseline slides unchanged.
Fresh core/renderer tarballs pass all 35 shipped-file hashes, the complete
Node/browser matrix, TypeScript 5.9.3 NodeNext/Bundler consumers and a zero-finding
dependency audit. Source and installed resource reports and every generated
source/container byte agree. Syntax and package validation pass. Reports and
logs use deterministic gzip; the manifest hashes stored/decoded evidence and
the relevant runtime, build and test sources.

The preceding collection CI at
[`9bd4d32`](https://github.com/OpenPresentation/opf-render/actions/runs/34928184737)
passed macOS/Windows Node and Linux browser, fresh-package and coordinated

Reproduce with coordinated Node 24 dependencies using `npm run test:shaping`,
`npm run test:shaping-browser`, `npm run test:shaping-packed`, and the full suite
with the reviewed furniture baseline. The independent resource check is optional
and test-only:

```sh
python test/font-dfont-fonttools.py
```

It requires `fonttools==4.60.2` in a temporary Python environment and the source
fixtures generated by `test/font-dfont.mjs`. The
[FontTools resource API](https://fonttools.readthedocs.io/en/latest/misc/macRes.html)
and [Apple font-table reference](https://developer.apple.com/fonts/TrueType-Reference-Manual/RM06/Chap6.html)
provide the resource/selected-sfnt boundaries used in this check.

Raw DFont resources are covered; MacBinary/AppleDouble wrappers and Type 1
suitcase conversion are separate formats. CFF/CFF2/variable instances, paragraph
itemization/bidi, fallback, lifetime/performance, complete slide/ink and shared
editing/export acceptance remain open. Fontkit remains the default, the prepared backend is opt-in, and native/font
release gates remain separate.
